The SDK works with both **JavaScript and TypeScript**. TypeScript is optional, but we strongly recommend it for SDK integrations: the included types help catch invalid method names, parameter shapes and response assumptions at build time, before requests reach the exchange. If you choose TypeScript, follow the [TypeScript setup](/environments/typescript) and run `npx tsc --noEmit` during development and CI. Type checking does not replace runtime validation or exchange-side checks.

Some runtimes can execute TypeScript directly. For example, [Node.js type stripping](https://nodejs.org/api/typescript.html#type-stripping) supports erasable TypeScript syntax without a separate compiler, but does **not** check types. If your runtime cannot execute the syntax used by a TypeScript example, compile that example to JavaScript or use a compatible TypeScript runner. Examples with local `.js` imports that refer to TypeScript source files can use the compiler-based setup above. Plain JavaScript usage does not need any TypeScript tooling.
